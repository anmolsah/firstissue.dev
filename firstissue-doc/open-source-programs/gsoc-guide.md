Google Summer of Code (GSoC) is a prestigious global online program that introduces new developers to open source software development under the direct mentorship of senior engineers.

## 1. Understanding the GSoC Timeline

GSoC runs annually from January through November. Understanding the key milestones is essential for proper preparation:

1. January - February: Mentoring organizations apply to participate.
2. Late February: Google announces accepted organizations and their Project Ideas Lists.
3. March - April: Contributor proposal window opens (2-3 weeks).
4. May: Accepted contributor projects are announced. Community Bonding period begins.
5. June - August: Official coding period (midterm evaluation at week 6, final evaluation at week 12). Extended projects can run up to 22 weeks.
6. September - November: Results announced, completion certificates, and final stipends disbursed.

## 2. The 3-Month Preparation Strategy

Don't wait until organizations are announced! More than 70% of participating organizations return each year (e.g., Apache Software Foundation, Linux Foundation, Python Software Foundation, CNCF, KDE, Mozilla).

> [!INFO] Pro-Contributor Rule
> Organizations strongly prioritize candidates who have already landed 2-4 PRs in their repositories before the proposal period closes. Early code contributions speak louder than promises.

- Pick 1 or at most 2 organizations that match your tech stack (e.g. Python, Go, TypeScript, Rust, C++).
- Join the organization's official chat channels (Slack, Discord, Zulip, Matrix, or mailing lists).
- Introduce yourself politely: mention your background, your timezone, and link to your GitHub profile.
- Browse open issues labeled 'good first issue' or 'help wanted' and request assignment.

## 3. Structure of a Winning Proposal

A successful GSoC proposal is treated like an engineering specification. Follow this proven structure:

- Project Abstract: 2-3 paragraphs defining the problem, proposed solution, and tangible user impact.
- Technical Architecture: API contracts, data models, third-party libraries, and sequence diagrams.
- Detailed Weekly Timeline: Break down the 12 weeks into concrete deliverables with buffer weeks for unforeseen bugs.
- Testing & Documentation Plan: Unit tests, integration tests, benchmarks, and developer guides.
- Prior Contributions: Links to merged PRs, open issues, and code reviews in the project.
- Availability & Commitments: Clarify your weekly working hours (e.g., 30 hrs/week) and university exams upfront.
