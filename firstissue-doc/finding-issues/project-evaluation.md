Not all open source projects are created equal. Learning to evaluate projects will help you find welcoming communities and successful contribution experiences.

## Signs of a Healthy Project

-  Clear README with setup instructions
-  CONTRIBUTING.md file with guidelines
- ️ Well-organized issues with proper labels
-  Maintainers respond to issues and PRs
-  Recent commits and releases
-  Reasonable number of stars and forks
-  Automated tests and CI/CD setup

## Red Flags to Avoid

-  No activity for months
-  Issues with no responses from maintainers
-  Rude or unwelcoming community interactions
-  No documentation or setup instructions
-  Hundreds of open issues with no organization
-  No tests or quality checks

## Evaluating an Issue

Before working on an issue, check these factors:

1. Is the issue description clear and detailed?
2. Has anyone else claimed to work on it recently?
3. Are there any linked discussions or related issues?
4. Does the maintainer seem responsive to questions?
5. Is the scope reasonable for your skill level?

> [!WARNING] Avoid These Issues
> Skip issues that are vague, very old (6+ months), have many people already working on them, or seem way above your current skill level.

## Testing Project Friendliness

Before diving deep, test the waters:

```text
1. Comment on an issue asking a clarifying question
2. See how quickly and helpfully maintainers respond
3. Check if they welcome newcomers warmly
4. Look at how they handle other contributors' questions
```
